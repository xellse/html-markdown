# 火柴人讲解动画（stickfigure-explainer）

把一个道理，或一个人想明白一件事的过程，做成 Ben Orlin 式火柴人动画。黑色墨线画在纸上，红笔批注，黄色荧光笔标重点，有年轻男声配音和轻快配乐，在浏览器里播放。

这套方法来自一个真实项目：给 8 岁的 Jasper（数学很深，心智仍是孩子）做的《数学少年陶哲轩》。第 1、2 集已经验收，源码在 `examples/`。

## 你要交付什么
- **一个可播放的网页**：`episode-N.html` 加 `episode-N.audio.js`，本地双击即可播放，也可以发布成 Claude Artifact。
- **一个项目仓库**：共享引擎加每集场景，下一集接着写。
- **每个确认节点的简短说明**：样片、大纲、每一集。

## 工作流（带 ✋ 的地方停下来等用户确认）
1. **准备环境**（一次）：
   - `bash <skill>/scripts/setup_env.sh`
   - `python3 <skill>/scripts/new_project.py <目录> --series "系列名"`：生成项目，里面有一集能直接构建的演示；先跑一遍 `python3 build.py ep1`。
2. **需求与观众画像**：年龄、心智、知识深度、在读什么书、性格上的"坑"、用途。
   - 缺信息就一次问完，最多 2–3 个问题。
   - 画像决定题目深度和语气，见 `references/narrative.md` 第 2 节。
3. **核查**：
   - 人物和历史类用网络检索，每条附出处。
   - 用户记错的事要礼貌更正，并把真相变成更好的故事。
   - 知识类的每个数字都要验算。
4. **10 秒风格样片** ✋：直接改演示或写一个短场景，发布给用户确认线条、颜色含义和主角造型。**要快**，不要为此开多方案评审。
5. **系列大纲** ✋：写 `script-outline.md`，内容包括主题、内外两条阶梯、观众画像、每集的事实、演绎和学习目标、出处。
6. **逐集制作** ✋：
   1. 先写逐句旁白，定时间；
   2. 再写场景，多的时候分给 3 个代理并行，用前缀隔离；
   3. 截图检查，至少改 2–3 轮；
   4. `tools/check_timing.py` 检查字幕时长，再用 `tools/audio.py` 生成配音和配乐包（它会自动重新构建页面）；
   5. `playtest.cjs` 测试播放器；
   6. 发布，写说明。

   细节见 `references/pipeline.md`。

## 不能丢的原则（以及原因）
- **颜色即意义**：黑色是故事，红色是旁白、批注和小问号，黄色是关键知识。孩子靠颜色读画面，挪用一次，颜色就失去意义。
- **知识要手写出来**：公式一笔笔写（`write`），文字和代码逐字出现（`scribe`）。看见"写"的过程，就是看见思考的过程。
- **一集一个核心道理**，故事和知识拧在一起：人物卡住了，靠知识走出来。知识插播孩子记不住，冲突记得住。
- **知识不降级，讲法童趣化**：聪明的孩子能接受真正的证明，真正要调的是句长、笑点和角色。
- **小问号是好奇的朋友**：它追问"为什么"，是真的想弄懂，被说服时开心点头。它一旦像在挑刺，孩子就会讨厌"讲清楚"这件事。
- **一切画面都是时间的纯函数**（`render(t)`）：拖动、截图、从任意时刻播放都可靠。不用随机数，不存上一帧的状态。
- **先写旁白，画面跟着旁白演**：旁白说到什么，画面就在演什么。一行字幕不超过 20 个字，时长至少 `0.2 秒 × 字数 + 0.8 秒`（按云希实测；`tools/check_timing.py` 会检查，`tools/audio.py` 用真实配音再核对一次）。
- **事实和演绎分开**：真实的事要有出处；演绎只能用来表现有记录的特点；泛指不能说成真实事件。
- **自己听不到声音**：音色、音量、配乐是否合适，要让用户判断；先给试听样本让用户选。

## 固定手法速查（详见 references/narrative.md 第 3 节）
| 手法 | 做什么 | 引擎里对应 |
|---|---|---|
| 红笔标注 | 一本正经的吐槽，例如"下巴（掉了）" | `label` |
| 手写知识 | 公式一笔一笔写出来 | `write` / `scribe` |
| 荧光笔 | 这一处是重点 | `highlight` |
| 红笔验算 | 旁边写上 ✓ | `write` 设 `color: 'red'`，加 `ring` |
| 印章 | 记录年龄、朝代、步骤 | `ageStamp`（`age` 或 `label`） |
| 小问号 | 追问"为什么" | `qm` |
| 小知识卡 | 故事暂停，讲一个旁支知识 | `factCard` |
| 三种写法 | 显然 → 举例 → 讲清楚 | 场景写法，见 `examples/tao-ep2/50_oddproof.js` |
| 反例 | 规律在第 N 次失灵 | 场景写法，见 `examples/tao-ep2/20_circles.js` |
| 轮到你了 | 停下来等孩子想 | 场景里的 `pauses` |
| 回调笑点 | 口头禅、下巴掉了 | `speech`、FACE 里的 `jaw` |
| 片头、回顾、尾声、预告 | 固定的开场和收尾 | `title`、`speech` |
| 程序一行行执行 | 打字、行指针、输出 | `codeBlock` + `varBox` |
| 任意位置的重点、划掉、圈出 | 代码、文字、区域都能用 | `band`、`strike`、`ringRect` |
| 计数、范围、循环 | 数轴上跳跃的小人、栅栏 | `numberLine` |

## 何时读哪份参考
- `references/narrative.md`：定故事、写旁白之前。包括观众画像、固定手法、一集和一个系列的结构、旁白规则、事实边界。
- `references/visual-style.md`：动手画之前。包括颜色、线宽、角色比例、字号、层级、动效节奏、配音配乐参数。
- `references/engine-api.md`：写场景时。包括场景格式、轨道、姿势和表情库、全部组件参数、自定义组件、命令。
- `references/pipeline.md`：规划制作和分工时。包括各步骤、并行代理说明模板、质检清单、发布步骤、沟通教训。
- `references/subjects.md`：题材不是人物传记时。包括数学题、编程、古诗词、物理、化学的改编方法、反例库、道具清单。
- `references/environment.md`：出错时。包括字体缺失、证书、ESM、推送、发布相关的问题。
- `examples/`：想看某个手法的真实写法时。`examples/README.md` 有索引。

## 常用命令
```bash
python3 build.py ep1                                  # 构建 → episode-1.html（没有音频包时用浏览器语音）
python3 build.py ep1 --only 10_,20_ -o /tmp/t.html    # 只构建部分场景（_ 开头的共享文件总会带上）
python3 tools/check_timing.py ep1                     # 生成配音前，先检查字幕长度和时长
python3 tools/audio.py ep1                            # 配音 + 配乐 → episode-1.audio.js，列出超时句子，并自动重新构建页面
NODE_PATH=$(npm root -g) node <skill>/scripts/capture.cjs episode-1.html frames "every:5" 1280
python3 <skill>/scripts/sheet.py frames sheet.png 4 480        # 用 Read 看这张图
NODE_PATH=$(npm root -g) node <skill>/scripts/playtest.cjs episode-1.html out
```
