# 跨学科改编：同一套叙事语言，讲不同的东西

所有学科共用一条主线：**看见 → 猜 → 被小问号追问 → 卡住，或被反例打脸 → 找到方法、讲清楚 → 回到开头把问题解决 → 金句**。

不同学科的差别只在三处：
- "手写"的是什么；
- 反例从哪里来；
- 需要哪些道具。

## 1. 数学题讲解
- **核心冲突**：一眼看出答案或规律，可是讲不清为什么；或者规律在第 N 次失灵。
- **手写**：算式用 `write`（引擎自带手写字形）；中文推理用 `scribe`；关键步骤用黄色，验算用红色 ✓。
- **反例库**（记得验算）：

| 例子 | 看起来的规律 | 实际 |
|---|---|---|
| 圆上连线分块 | 2、4、8、16 | 第 6 个点时是 31，不是 32 |
| n² + n + 41 | 从 0 到 39 都是质数 | n = 40 时是 41² |
| 快乐数 | 试几个就下结论 | 要证明"大数会变小" |
| 奇数 + 奇数 | 举三个例子都对 | 要用点阵证明对所有奇数成立 |

- **可视化证明库**：
  - 点阵、L 形拼图：奇数之和是平方数；
  - 两两配对：奇 + 奇 = 偶；
  - 首尾配对：1 + 2 + … + 100；
  - 黑白染色：残缺棋盘不能用骨牌铺满；
  - 奇偶周期：斐波那契数每三个出现一个偶数；
  - 数值逼近画成折线：极限。
- **一集样板**（约 3 分钟）：
  1. 题目：主角一眼答出；
  2. 小问号问"为什么"；
  3. 三种写法对比（显然 / 举例 / 证明）；
  4. 画图证明；
  5. 推广（数字变大、换成 n）；
  6. 轮到你了（停顿）；
  7. 金句。
- **示例旁白**：
  - "一个四位数，每一位最大是9，" [say: 一个四位数，每一位最大是九，]
  - "比1000小多了！" [say: 比一千小多了！]
- **坑**：
  - 题太简单，聪明的孩子会失去兴趣。选"一眼能猜、证明有趣"的题。
  - 所有数字都用脚本验算。

## 2. 编程逻辑
- **核心冲突**：程序在小数据上都对，一到边界就错；或者"我知道它会输出什么"，结果不是。
- **角色映射**：
  - 主角是写程序的孩子；
  - 小问号还是小问号，也可以改名"小 Bug"。它的台词是"这里为什么是 < 不是 ≤？""如果列表是空的呢？"。
  - 可以加一个"电脑"角色：屏幕上有两只眼睛，一板一眼地执行。
- **手写**：代码用 `scribe` 逐字出现，字体用 VT323（屏幕上的代码）或 Patrick Hand（写在纸上的代码）。**不要用 `write`**，它不支持字母。
- **执行动画**（都要写成时间的纯函数）：
  - **程序计数器**：一只红色小手指，按时间逐行下移（`pos` 轨道）。
  - **变量盒子**：带标签的方框，值在指定时刻改变，旧值被红笔划掉，新值手写进去。
  - **循环**：沿用快乐数的"绕圈"画法，数字排成环形，一个小红点绕圈跑。
  - **递归**：盒子套盒子；或者印章一层层盖下去，再一层层弹回来。
  - **调用栈**：一叠卡片，入栈时往上叠，出栈时移开。
  - **排序或查找**：数字卡片交换位置（位置轨道），比较时两张卡片抖一下。
- **反例库**：
  - 差一错误（off-by-one）：循环少跑或多跑一次；
  - 空列表；
  - 整数溢出，例如计算器的数位满了；
  - 浮点数 0.1 + 0.2 不等于 0.3（这一条要在真实环境里验证）。
- **三种写法**：
  1. 没有注释、变量叫 a、b；
  2. 注释写"这里是循环"这类废话；
  3. 名字说清楚意图，边界条件写明白，再附一个测试。
- **轮到你了**：预测输出，停下来想，再揭晓。
- **配乐**：chip（8-bit）。电脑道具可以参考示例 `examples/tao-ep1/20_age6.js` 里的复古电脑。
- **核查**：每段代码都要真的跑一遍，屏幕上显示的输出必须是真实输出。

## 3. 古诗词
- **核心冲突**：为什么是这个字？为什么这样写，不那样写？诗人也改过很多遍。
- **角色映射**：
  - 诗人是一个有特征的火柴人（胡子、斗笠、官帽的简笔）；
  - 小问号问"为什么用'绿'，不用'到'？"；
  - 主角是读诗的孩子。
- **印章**：`ageStamp` 用 `label` 写朝代和年份，例如"北宋"，`place` 写地点，例如"瓜洲渡口"。
- **手写诗句**：用毛笔字体逐字出现（`scribe`）。
  - 在 `src/shell.html` 的 Google Fonts 链接里加 `family=Ma+Shan+Zheng`（或 Zhi Mang Xing、Long Cang），组件里写 `font: "'Ma Shan Zheng', serif"`。
  - 注音、释义用红笔标签；"诗眼"用黄色。
- **画面**：用墨线画意象，例如月亮、江、船、柳、山。一句诗对一个画面，画面随诗句一笔一笔画出来。
- **三种写法对比**，用诗人真实的推敲过程：
  - 王安石"春风又绿江南岸"。据南宋洪迈《容斋续笔》，草稿里先后用过"到""过""入""满"，最后定为"绿"。
  - 贾岛"僧推（敲）月下门"的"推敲"故事。
  - 这类记载要标明出处，并注明"据某书记载"。
- **节奏**：旁白放慢，语速设为 +0% 或 -5%。朗诵诗句单独成行，前后留 0.5 秒。可以在 `audio.voices` 里加一个朗诵声音。
- **配乐**：换成古琴、古筝一类的曲子，必须确认授权，并在 tracks 里写明 author 和 license。
- **坑**：诗句、作者、朝代都要核对原文，注意版本差异。没有记载的"创作场景"只能写成想象，并明确说出来。

## 4. 物理
- **核心冲突**：直觉会骗人，例如"重的东西落得快"；只有测量和实验说了算。
- **角色映射**：
  - 主角做实验、记数据；
  - 小问号问"你怎么知道？""再测一次呢？"。
  - 科学家角色出现时，适用第 6 节的事实规则。例如伽利略比萨斜塔实验很可能只是传说，要说"传说"。
- **运动必须真实**：位置由真实公式算出，并且是时间的纯函数。
  - 自由落体：`y = y0 + ½·g·t²`，按舞台比例换算。
  - 单摆：`θ = θ0·cos(√(g/L)·t)`。
  - 可以"慢动作"：在同一个场景里把 t 换成 `t·0.25`，旁边用红笔标注"慢 4 倍"。
- **测量**：画一张手写表格，数字一个个写进去（`write`）。接着像 `examples/tao-ep1/26_ratio.js` 那样，把数据点画到手绘坐标图上，再连线。
- **颜色**：
  - 力和速度的箭头用墨线；
  - 正在讨论的那个量用黄色；
  - 红色仍然只给旁白和小问号，不要拿红色画力。
- **反例库**：
  - 重物和羽毛：有空气时羽毛慢，真空里同时落地（真实实验的影像可以链接出去，不要嵌入）；
  - 单摆周期几乎不随摆幅变化（小角度时）；
  - 冰浮在水上：固体反而比液体轻，是水的特殊之处。
- **配乐**：calm 或 sneaky；实验成功时响 tada。

## 5. 化学
- **核心冲突**：东西"消失"了，还是变成了别的？质量守恒、原子重新组合。
- **粒子动画**：每个粒子的位置 = 基准点 + 由自身编号决定的小幅振动（用 `rnd(hash, i, 0)` 得到相位，再用 sin 或 cos 振动），保证是时间的纯函数。温度越高振幅越大。反应就是粒子按时间插值换位置、重新组合。
- **数原子**："反应前 4 个 H、2 个 O；反应后……"。数原子就像数学里的证明，是这个学科的"讲清楚"。
- **颜色变化**：墨线画面表现不了颜色，用红笔标签写"变蓝了"；或者给这个实验单独开一种颜色，写进本集规范。
- **反例库**：
  - 蜡烛烧完"变轻了"：生成的气体跑走了，在密闭容器里称，质量不变；
  - 铁生锈反而变重：铁和氧结合了。
- **安全**：不要把危险实验演成可以在家做的事，需要时加红笔提示"请在大人陪同下"。
- **核查**：化学式、配平、现象描述都要核对。

## 6. 人物传记与历史（《数学少年陶哲轩》的做法）
- **外在阶梯**：年龄印章串起全系列，例如 2 → 7 → 8 → 9 → 10 → 13 岁；再加上可见的成就，例如铜 → 银 → 金。
- **内在阶梯**：人物的思维方式在变，这是真正的主线。
- **事实**：每条都要有出处，优先用一手资料。在大纲里把事实和演绎分两栏列出来。
- **引用原话**：用原文，报纸标题、程序代码都可以用原文，再配红笔翻译。真实文字比编的台词更打动人。
- **真人出镜**：画成火柴人加一个特征（眼镜、卷发），不画肖像；名人的名言要核对出处。
- **用户记错的事**：直接更正，并把真相变成更好的故事。
- **配乐**：每个人生阶段一个主题，例如编程时用 chip。
